## Purpose

How the console behaves when an operator creates, changes, deletes and watches resources (`L2-001` CON-13 – CON-18). Visual tokens are in `L2.5-001`; this document fixes the interaction rules so every kind behaves the same.

## 1 · Create

- "New <kind>" (dark pill with a plus icon) opens a **side panel** over the detail pane (a full screen on phones). The list stays visible so the new row can appear in place.
- Fields validate **on blur and on submit** with the same rules as the API (`L3-002` §4); the message sits under the field, in plain words, naming the rule ("Use 3–40 lowercase letters, numbers or hyphens, starting with a letter").
- Server validation errors map to their field by `details[].field`; anything else shows above the submit button with the request ID.
- Submitting closes the panel, selects the new resource and shows its progress. A toast confirms ("Creating database orders").
- Key–value editors (environment, secret environment) add rows with "Add variable"; secret environment picks from existing secrets in a select, with "Create secret" inline.

## 2 · Edit

- "Edit" on the detail opens the same panel prefilled. Fields that cannot change in place are read-only with a one-line reason ("Changing the version needs a new database").
- Saving sends only the changed spec with the version it was read at; a conflict ("This changed since you opened it") offers Reload.

## 3 · Delete

- "Delete" opens a dialog naming the consequence ("This deletes the database orders and all of its data. This cannot be undone.") and requires typing the name. The confirm button stays disabled until it matches.
- Refusal because of dependants lists them as links.
- The row shows "Deleting" until the resource is gone, then disappears and selection moves to the next row.

## 4 · Progress, failure, retry

- Phases are words with a dot, never colour alone: Pending, Provisioning, Updating, Deleting (amber, pulsing), Ready (green), Failed (red).
- The step track (Pull → Create → Start → Healthy) fills as steps complete; a failed step turns red and the phase message appears under the heading with a **Retry** button.
- While anything is in progress the detail and the list poll every second; otherwise the list refreshes quietly every 5 seconds, so resources created from the CLI or OpenTofu appear without a reload (ADR-003). Create and edit forms load the secret list fresh each time they open.

## 5 · Secrets

- Values are write-only in forms (password-type input with Show toggle while typing).
- Reveal asks for confirmation, shows the value in a monospace box with Copy, and hides it again after 30 s or on navigation.

## 6 · API tokens

- The new token is shown once, in a box with Copy and the warning "You won't see this token again". Closing the box requires an explicit "I've copied it".
- Revoke asks for confirmation naming the token.

## 7 · "Use from code"

Every resource detail ends with a collapsible "Use from code" section: the CLI command that would create it as it is now, and the OpenTofu block, each with Copy.

## 8 · Empty and error states

- An empty section explains the kind in one sentence and shows "New <kind>".
- A list or detail that fails to load shows the message and Retry; an engine outage shows a banner on every page ("Docker isn't running. Changes are queued and will apply when it's back.").

## 9 · Layout (v3)

*Replaced by §16 as each step of the console v4 ships.*

- **Sidebar**: brand, then "Resources" (each kind with an icon in a circle, label, count) and "Settings" (API tokens); at the bottom a memory card with a progress bar, then the signed-in user with a sign-out icon button. Phones: a drawer.
- **List column**: a rounded panel titled with the kind ("Apps"), a sub-line ("3 apps · newest first"), round icon buttons for search and "New". Items are cards: avatar, name, one-line status, chips (phase, key fact) and a right-hand badge (published port, version or step count).
- **Detail panel**: action pills on top (Restart, Redeploy, Edit, Delete); a header with a large avatar, the name, a sub-line and chips; key facts on the right (phase, memory, port, created). Below, the stage pill and the primary action, then segmented tabs, then a grid of cards (Connection, Settings, Use from code; Value for secrets).
- **Top bar**: breadcrumb (machine › kind › resource) and round icon buttons (new, theme), plus the user's avatar.

## 10 · v0.3 patterns (planned)

- **Domains.**
  - A domain card shows the hostname as a link, the target ("→ api :8080") and a certificate chip ("Certificate · expires 12 Jan", "Waiting for DNS", "Local certificate").
  - While waiting for DNS, the detail shows the exact record to create in a copyable block: type, name, value. The value is the configured public address, or a field to set one.
  - **Local certificate**: one card explains what trusting the EnclaveStack root does, with a download button and steps per platform.
- **Deploys.**
  - During a deploy, the stage pill reads Start → Health check → Switch traffic → Stop old.
  - The health-check step shows "Attempt 3 of 12 · last: connection refused".
  - A discarded revision ends with a red message: "Revision 8 failed its health check. Revision 7 is still serving." The message has **Retry** and **View logs** buttons.
- **Schedules.**
  - Cron schedules are always shown in words next to the expression ("Every hour at :00"), plus the next run in local time with the time zone named.
  - The schedule field describes itself in words and previews the next three runs as the user types, when the job's zone is the browser's (or empty); otherwise it shows the words only, because the browser can't reliably compute another zone's cron times. The server's `nextRunAt` is authoritative.
- **Runs.**
  - A Runs tab lists runs newest first: status chip, trigger, started, duration, then exit code (jobs) or size (backups).
  - Opening a run shows the output tail in the dark terminal surface, with a notice that output is stored as printed.
- **Backups** *(shipped)*.
  - Databases and caches have a Backups tab: the backups that cover them, or "Set up backups", which opens the backup form with the source filled in.
  - A backup's toolbar has **Back up now**. Its Runs tab shows size instead of exit code, and has **Details** (object key, destination, size, SHA-256) and **Restore** on runs that can still be restored.
  - Deleting a backup says its stored backups are kept.
  - An empty picker reads "Choose a bucket." or "Choose a database.", never the API's exactly-one rule.
- **Restore** *(shipped)*.
  - **Restore** opens a drawer with two `Choice` cards. The first, selected by default, is "Into a new database" (or cache). Its name field is prefilled `<source>-restored`, and it explains that the source keeps running untouched.
  - "Replace the data in <source>" shows a warning and needs the source name typed. The button stays disabled until the name matches. The drawer says that a safety backup is taken first.
  - After either choice, the console opens the database or cache being restored, so its progress and result are in view.
- **Git source** *(shipped)*.
  - The app form starts with "Deploy from": two `Choice` cards, "An image" and "A Git repository".
  - The Git fields are the repository, the branch/tag/commit (prefilled `main`), the Dockerfile, the build context, credentials (a secret, or "None (public repository)") and build-argument rows, whose hint says "not for secrets".
  - A source app's Overview shows "Source: <url> @ <ref>", the built commit, the built image and the last build ("Skipped — nothing changed" when a redeploy found nothing new).
  - A **Build log** tab shows the latest build in the terminal surface, with error lines in red.
  - A failed build's message names the failing step and says the serving revision keeps running.

## 11 · v0.4 patterns (shipped 2026-10-21)

As built, where it differs from the plan below:
- The **DNS** section lists zones; a zone's **Records** tab is a table (name, type, value, TTL, status) with **Add record**, which opens the record form with the zone filled in. Records keep their own pages (`/records/<id>`) for editing and links, and aren't a sidebar entry.
- Rule rows are a protocol select, a ports field and a sources field that suggests `any`, networks and resources and also takes CIDRs; targets are a checklist.
- The record form labels the name inside the zone **Record name**, so it can't be confused with the resource's name.
- The delete dialog names the kind in words ("Delete load balancer").

- **Networks.**
  - A network card shows its CIDR, "Internet" or "Private", and "3 resources".
  - The form takes the CIDR (prefilled with a free `10.x.0.0/16`) and subnet rows (name, CIDR). Each row says how many addresses it holds and turns red when it is outside the network or overlaps another row.
  - Resource forms have a **Network** section: a network picker ("Default network" first) and, once one is chosen, a subnet picker. A network without internet disables **Publish** with the reason.
  - A placed resource's Overview shows the network, subnet, private IP and its private DNS name with a copy button.
- **Firewalls.**
  - A firewall's detail reads its rules as sentences: "Allow tcp 5432 from app/api", "Allow all from network/backend", "Deny other outgoing traffic".
  - The editor has a **Targets** multi-picker and rule rows. Each row has a protocol choice, a ports field (`80, 8000-8100`) and a sources picker that lists networks and resources, or takes a CIDR.
  - A resource covered by firewalls shows a **Firewalls** card listing them, and "Accepts everything" when there are none.
  - The firewall detail says once, in plain words, that published host ports stay reachable through the machine.
- **Replicas and load balancers.**
  - The app form's Deploys section gains **Replicas** (1–10); it is disabled at 1 while **Publish** is on, with the reason.
  - An app card shows "3 replicas". During a deploy, the health step reads "Replica 2 of 3 · attempt 1 of 12".
  - A load balancer card shows protocol and port, and a healthy-targets meter ("5 of 6 healthy").
  - The form has target rows (app, port, weight), an algorithm choice and a health check section. Targets from another network than the first are refused with the reason.
- **DNS.**
  - One **DNS** section lists zones; a zone's detail lists its records as a table (name, type, value, TTL), with **Add record**.
  - Creating a zone asks for the provider (`Choice` cards: Cloudflare, Route 53), the zone name and the credentials secret, and shows the permissions the token needs. A ready zone shows its name servers.
  - The record form takes the name (with the zone shown after it: `api` `.example.com`), the type, and either values or **Point at this machine** (A and AAAA only), which shows the current public address or a link to set one.
  - A record that conflicts shows the values found at the provider next to the ones asked for, and says to change them there or pick another name.
- **Domains through DNS.**
  - The domain form gains **Get the certificate through DNS** with a zone picker. Only with it on does the hostname accept a leading `*.`; the hint says so.
  - During issuance the certificate step reads "Creating the challenge record", "Waiting for Let's Encrypt to check it", "Certificate issued".

## 12 · v0.5 patterns (shipped 2026-10-21)

As built, where it differs from the plan below:
- **VMs unavailable**: the VMs section shows an alert with the reason and the fix as a copyable code block; the machine card adds a quiet "VMs unavailable" line with the reason as its tooltip.
- **Take snapshot** asks for the name in the snapshot form (source filled in) rather than a prefilled `<source>-<date>` name.
- The VM detail's Overview has a **Connect over SSH** card with both commands; the Boot console tab shows the last lines, without following live.
- The design system gained the **Camera** (snapshots) and **Power** (stop) icons; VMs use **Server** and volumes **HardDrive**.

- **VMs.**
  - A VM card shows its power state as a status (Running, Stopped, Starting, Stopping) next to the lifecycle phase, then the image, "2 CPUs · 2 GiB", and the private IP.
  - The form starts with the image. `Choice` cards offer Ubuntu 24.04, Debian 12, **From a URL** (URL and an optional SHA-256) and **From a snapshot** (a picker of disk snapshots). Then comes the size: preset `Choice` cards (Small 1 CPU · 1 GiB, Medium 2 · 2 GiB, Large 4 · 8 GiB, Custom) fill CPUs and memory, which stay editable, and the limits come from `GET /machine`. Then the root disk in GiB.
  - **Access** takes SSH keys pasted one per line, with each key's type and comment shown back, or a secret. A hint says keys and the first-boot script can't change later.
  - **First boot** is a code field that accepts `#cloud-config` or `#!`, with a size counter.
  - Below come the **Network** section (as §11), **Disks** (free disk volumes only; attached ones are listed as unavailable with the VM that has them) and **Publish** ports.
  - The detail's Overview shows `ssh enclave@127.0.0.1 -p 2201` and `enclave vm ssh <name>`, each with a copy button. Header actions are **Start** or **Stop** (whichever applies) and **Restart**. A **Boot console** tab shows the console log in monospace, following new lines while open.
  - **Restart warnings.** Saving a change that restarts the VM (CPUs, memory, disks, network while running) opens a confirmation that names the changes and says "worker will restart". Nothing is sent until it's confirmed. Changes that don't restart (power, publish, root disk growth) save directly.
  - **VMs unavailable.** While VMs can't run, the machine card shows "VMs unavailable" with the reason and the command in a copyable code block. The VM form's submit is disabled with the same text. Existing VMs say "Waiting for QEMU".
- **Volumes.**
  - A volume card shows its type ("Disk · 50 GiB" or "Filesystem · 1.2 GiB used") and what it is attached to, as links ("vm/worker", "app/web").
  - The form asks for the type (`Choice`: Disk for VMs, Filesystem for apps and jobs), the size for disks, and an optional snapshot. The snapshot picker lists only snapshots of the chosen type.
  - App and job forms gain a **Volumes** section with rows: a filesystem volume picker, a path (must start with `/`) and a read-only toggle. A hint says that changing them deploys a new revision.
  - Growing a disk shows the new size and "Grows while the VM runs; it can't shrink". A lower size is refused as you type.
- **Snapshots.**
  - A snapshot card shows its source as a link, its type, its size and when it was taken. A filesystem snapshot taken in use carries the note "Copied while in use".
  - **Take snapshot** sits in the header of every volume's and VM's detail and opens a dialog asking only for the name (prefilled `<source>-<yyyymmdd-hhmm>`).
  - From a snapshot's detail, **Create volume** opens the volume form prefilled with the snapshot. **Launch VM** opens the VM form with **From a snapshot** chosen. Both stay available after the source is deleted.

The detail's **Connect** card shows a connection string in the engine's own form (`mysql://…`, `mongodb://…?authSource=admin`, `http://…:8123`) with `<password>` in place of the password, and a Reveal link to the password secret.

  - The form groups **Delivery** (visibility timeout with a seconds/minutes unit picker, maximum receives) and **Keeping** (retention in hours, maximum size), and the dead-letter queue picker appears once maximum receives is above 0.

The detail links to the message viewer (`webUrl`).
- **Icons.** The design system gains icons for queues (`ListOrdered`), topics (`Radio`), search (`TextSearch`, since `Search` already means finding things in lists), transcoders (`Clapperboard`), CDN (`Rocket`, since `Globe` is domains) and email (`Mail`), and `Send` and `Inbox` for sending and receiving.

## 16 · Console v4 layout and navigation (planned)

*Step (a) built 2026-10-22: the grouped floating sidebar with its rail, the breadcrumb in the top bar (every step but the last a link, built once from the address; a resource page adds its name), full-width section tables and full-page resources and machines with a Back link. As built, the breadcrumb sits in the top bar for every page rather than in each page's header, so one place builds it. Monitoring opens on its list, with "This machine" first.*

*Steps (b) – (d) built 2026-10-23. As built: Overview sits above the groups as its own link; the overview refreshes every second while anything is in progress, every 10 s otherwise, and its quick actions open a section with `?new=1`, which opens the create form (viewers get none). Find shows nothing until something is typed, then up to 12 results; each section page carries a Guide button and, once it has resources, a strip of numbers by state; DNS records share the zones guide. Field hints cover the forms that create or change a resource. Tables sit on a card and highlight the row under the pointer. Not built: the top bar's "New" menu (the overview's quick actions and each section's New button cover it).*

Requirements `L2-001` CON-61 – CON-69; look `L2.5-001` §7. Built in four steps, each one reviewed in the browser before the next: **(a)** sidebar groups, page header with links, full-page resources; **(b)** the overview; **(c)** section summaries and guides; **(d)** the calmer look, hints and motion.

### Shell
- A floating dark **sidebar** on the left; the page scrolls beside it. Top: the brand and the **project** menu (a `MenuSelect`: a button showing the folder icon, the current project and a chevron; it opens a dark list under it with the current project ticked, "All projects" first, then projects by name; arrow keys, Home, End, Enter, Escape and a click outside work; a native select is not used because its list cannot be styled). ### Find (CON-62)
⌘K / Ctrl+K or the top-bar box opens a dialog: a text field and results as you type — pages and guides first, then resources by name with their kind and state. Arrow keys move, Enter opens, Escape closes. `/` still focuses a section's own search.

### Page header (CON-63)
Every page starts with: the breadcrumb — machine › project › section › resource, every part but the last a link (the machine opens Machines, the project the section filtered to it) — then a Back button (resource pages only), the title, one line saying what this is, and the page's actions on the right. On a resource page the title carries its state as a dot and a word.

### Section page (CON-64, CON-66)
- The header: the section's name, its one-line blurb, **New <kind>** and **Guide**.
- A strip of stat tiles: total, running, in progress, needing attention (only the ones that apply).
- The list, full width: a table on wide screens (name, state, key fact, project when all projects show, machine when there are several, last changed); rows are links to the resource's page. Search filters it; `/` focuses search. Phones: one card per row.
- Empty: what the section is for in two sentences, **New <kind>** and **Read the guide**.
- **New** opens the create form in the side panel as today; when it's done, the new resource's page opens.

### Resource page (CON-64)
The header, then the stage track while something is in progress, then text tabs (Overview, Metrics, Logs, Environment, Events… as today) and their content full width. Facts sit in a grid of small cards; "Use from code" stays at the end of Overview. Deleting goes back to the section.

### Overview (CON-65)
At `/`. Top to bottom:
1. Header: "Good morning/afternoon/evening" and one line — "Everything is running." or "2 resources need attention." — with quick actions: New app, New database, Catalogue.
2. Stat tiles: **Running** (resources ready), **Need attention** (failed resources and firing alerts; red only when above 0), **Machines online** ("2 of 2"), **Memory reserved** ("1.2 GiB of 8 GiB" with a thin bar).
3. Two columns. Left, wide: this machine's charts for the last 24 hours (CPU, memory, disk full, failed resources; the charts of `L2.5-002` §14). Right: **Needs attention** — each failed resource or firing alert with its reason and **Retry** or **Open**; "Nothing needs attention" when empty.
4. Two columns. **Recently changed**: the ten resources changed last, with kind, state and when. **What's running**: each sidebar group with its counts by kind, every line a link.
Everything follows the project picker; the overview refreshes every 10 s.

### Guides (CON-67)
`/guide/<section>`, linked from the section header, its empty state and Find. One page per section, written for someone new to the idea:
- **What it is** (blue) — two or three plain sentences.
- **When to use it** (green) — three to five real situations as short bullets.
- **How to use it** (violet) — numbered console steps, then the same thing as one `enclave` command in a code block.
- **Example** (teal) — one small scenario end to end (e.g. a blog app with a database, a bucket for images and a domain), naming the resources it creates and how they connect.
- **Good to know** (amber) — limits, what it takes from this machine (memory, disk), the usual mistakes.
Then "Related" links to other guides, and last **Want more detail?**: one line saying the website's full guide covers every setting, the API and OpenTofu and describes the latest release, and a button that opens `https://enclavestack.soupler.com/services/<section>/` in a new tab (DNS records open the zones page). The website's address is one constant beside the guide copy. Guides speak about EnclaveStack only; they don't compare it with other companies' products. Copy lives with the section definitions, one source for the sidebar, Find and the guide.

### Motion (CON-68)
CSS only (`L2.5-001` §7): page and card entry fade, hover lift on cards and rows, sidebar groups and the rail animating their size, chart lines drawing in, numbers counting up. Nothing moves under reduced motion.

## 21 · Public access (`L2-014` CON-76 – CON-80)

- **Navigation.** **Tunnels** joins the Networking group after CDN: Networks, Firewalls, Domains, DNS, CDN, Tunnels. It has a guide like every section (CON-67) and a page on the website (`/services/tunnels/`), added there afterwards.
- **Catalogue: Public access** (CON-80). The catalogue gains a **Public access** category: six cards in two groups.
  - **An address for one app**:
    - **Quick link**: "No account, no domain. A random address that changes when it restarts, for demos."
    - **Tailscale**: "Free account. A stable name.ts.net address, private to your own devices or public."
    - **ngrok**: "Free account. One address per account; monthly limits, and a warning page before visitors."
    - **Custom**: "Any other tunnel service, from its own container image."
  - **Your own domain**:
    - **Cloudflare**: "Free. Your domain's DNS must be at Cloudflare."
    - **Your own server**: "A small server you rent. No third party sees your traffic."

  Each card shows what it needs, what it costs and, for a way in that needs an account, a **Sign up** link to the provider. **Install** on a built-in card opens the same form as **Tunnels › New tunnel**, set to that provider (`/tunnels?new=1&provider=…`); a template of your own in the category installs as a stack. `/catalogue?category=public-access` shows only the two Public access groups.
- **Tunnel form.** The same six cards, then only the fields of the choice:
  - **Cloudflare**: the credentials secret `Select`, with a hint listing the token's permissions (the token itself, or `{"apiToken": "…"}`), and the account ID.
  - **Your own server**: the edge machine `Select`, or "Add an edge machine first" linking to Machines.
  - **Tailscale**: the auth key secret, with a hint saying where to make a reusable key; **Private** / **Public** `Choice`s; the device name.
  - **ngrok**: the token secret and an optional reserved domain.
  - **Custom**: image, command, environment rows, secret rows, the public URL, and a hint "Send traffic to $ENCLAVE_UPSTREAM."
  - **Every app link**: the app, the port and the **Gate** (below).
- **Make public** (CON-80). An app's page header gains **Make public** (disabled, with a tooltip, while the app has no port). It opens a panel with two cards: **An address for this app** (Quick link always, and each other app-link way in once one of its kind is installed, so its account is set up), each with **Use …**, which opens the tunnel form with the app and way in filled in; and **Your own domain**, each Cloudflare or own-server tunnel with its state and **Add a domain through …**, which opens the new domain form with the app and tunnel filled in. **Install another way in** opens the catalogue's Public access category. Afterwards a **Public addresses** card on the app's page lists each address (Copy, Open), its way in and its gate.
- **Tunnel page.** Beside the phase, a ready tunnel's header has a **Connected** chip (green) or **Reconnecting** (amber). Details: the way in, the app, who can open it (Tailscale), connection and connections, the credentials secret (a link), the account ID, the edge machine, a custom image, open paths, and the outputs (tunnel ID, public address, device name, gate). A **Serves** card lists its public domains, each a link with its gate. An app link shows its URL large, with **Copy** and **Open**. A quick link adds "Temporary: this address changes when the link restarts, and handles at most 200 requests at once." A Tailscale link adds **Private: only your tailnet's devices** or **Public on the internet**. An ngrok link adds the free plan's limits. When the URL changes a toast says so.
- **Domain form: Public access.** A fieldset after the port:
  - two `Choice`s, **Only on this machine** (default) and **From the internet**;
  - **From the internet** shows: the tunnel `Select` (Cloudflare and own-server tunnels; "No tunnel yet" links to Tunnels with `?new=1`); the zone `Select` (required for Cloudflare, with PUB-02's message when the zone isn't at Cloudflare; optional for a relay, with the hint "With a zone, EnclaveStack writes the DNS record. Without one, you point it yourself.");
  - the **Gate** as three `Choice`s:
    - **Sign in** (default): "People with access to this project sign in with their EnclaveStack account."
    - **Password**: a secret `Select`, "Share one user name and password, for example with a client."
    - **Open to everyone**: choosing it opens a `ConfirmDialog`, "Anyone on the internet can open stage.galiaraa.com.", with **Open it to everyone** / **Keep a gate**.
  - **Open paths**: rows, "Paths that skip the gate, for webhooks from other services";
  - for Cloudflare tunnels, **Cloudflare Access**: emails and email domains as rows, "Cloudflare checks these people with a one-time code before EnclaveStack's gate."
- **Domain page.** A public domain's header has a chip **Public via home**; once ready, a card above the details shows the URL with **Copy** and **Open**. A **Public access** card shows the tunnel (a link), the DNS record (type, name, value and its state: Created, Already there, Different value — fix it at your DNS provider, or Point it yourself, with the record to add in a `CodeBlock`), the certificate ("Served by Cloudflare", or EnclaveStack's with its expiry), the gate (**Sign in**, **Password** with the secret's name, or **Open to everyone** in amber), open paths, and Access emails and domains. Its HTTPS and HTTP details are left out: the tunnel decides them.
- **Machines: Add an edge machine.** A second button beside **Add machine** (and `/machines?edge=1`, which the relay form links to) opens a panel: "A small server you rent with a public address. It relays visitors for your own domains to this machine over an encrypted tunnel; nothing else runs on it.", then name, public address and an optional agent port. After create: the join command in a `CodeBlock` with Copy, and the ports to open on that server (the agent's 7071/tcp from this machine only, 51820/udp, and 80/tcp and 443/tcp for visitors). **Done** opens the machine's page, whose state changes from **Waiting** to **Online** without a reload. The list marks it **Edge**. An edge machine's page shows the **Edge** chip, the role "Edge (only relays visitors)", a **Relays** card (links, or **Add a relay**) instead of **Runs here**, and no **Pause placing** or **Drain**.
- **The gate's pages** (served by the control plane, not the console). They use the design system's tokens and fonts in a centred card:
  - the logo, then "**stage.galiaraa.com** is private";
  - "Sign in with your EnclaveStack account to continue.", then email, password and **Continue**; an error appears in a `Banner` above the fields;
  - "This environment is private." with "Signed in as … · Sign out" for people without access;
  - "You're signed out of stage.galiaraa.com."

  Light and dark follow the visitor's system. They have no scripts. They work at 320 px wide.
- **Zones (PUB-09, PUB-10).** The zone form opens with an info `Alert`: "EnclaveStack writes, changes and deletes only the records of its own domains and records. Anything else in the zone, like production on another cloud, is never touched. Another environment on the same domain gets its own project and its own subdomain zone, like stage.example.com." The zone field's hint takes a whole domain or a subdomain zone ("like example.com or a subdomain zone like stage.example.com").
- **Use from code** on tunnels and domains shows `enclave tunnel create …`, `enclave domain create … --tunnel … --gate …` and the `enclave_tunnel` / `enclave_domain` blocks.
